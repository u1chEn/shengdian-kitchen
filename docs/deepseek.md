# DeepSeek 接入与隐私边界

## 已实现

`POST /api/recipes` 是服务端代理。线上 Worker 和本地 Node 预览共用同一个处理函数；本地密钥从服务端环境变量读取；线上支持用户在独立连接页配置自己的密钥，由服务端加密保存。默认供应商为 DeepSeek，默认模型为 `deepseek-flash`，非思考模式，JSON 输出，单次最多3道菜、2400输出token、40秒服务端超时。没有自动重试，也不会偷偷换供应商。

前端默认仍用内置菜谱。用户单独选择“用 DeepSeek 想几道”后，先显示本次发送预览，勾选并确认才会请求生成。打开预览仅检查本站配置状态，不调用外部模型。未配置密钥时按钮不可生成。

## 密钥如何配置

### 本地运行源码包

1. 将 `.env.example` 复制为 `.env`。
2. 在本地 `.env` 中为 `DEEPSEEK_API_KEY` 填入自己的密钥。
3. 保留 `AI_PROVIDER=deepseek`、`DEEPSEEK_MODEL=deepseek-flash`。
4. 使用 `node --env-file=.env server.mjs`，打开终端中的本地地址。
5. 在网页里选择食材，打开 DeepSeek 预览，核对内容后确认生成。

`.env` 已加入忽略规则，不上传GitHub、不发到聊天、不填进食材栏。普通 `node server.mjs` 不会自动读取 `.env`，所以没有配置时也能继续体验内置菜单。

### 当前在线网站

打开本站 `/connect.html`，登录后输入自己的 DeepSeek API Key，点击“加密保存密钥”，再返回冰箱选择食材、预览并确认生成。保存只检查格式，不请求 DeepSeek、不验证余额、不产生模型费用；实际可用性以第一次主动生成的结果为准。页面可以替换或删除自己的密钥。

- 服务端按平台验证的 `oai-authenticated-user-id` 隔离凭据，HMAC 生成不含身份明文的对象名。
- 凭据使用 Web Crypto AES-256-GCM、每次随机12字节IV、绑定对象名的认证数据加密后保存到私有R2；不存储明文密钥。加密主密钥 `SETTINGS_ENCRYPTION_KEY` 单独放在 Sites runtime Secret，不能写入仓库或用户数据对象。不要在未迁移数据前轮换主密钥，否则已有凭据无法解密。
- 凭据读写只在服务端；GET只返回配置布尔值，不返回原密钥、片段或密文。输入框保存后清空，页面不使用 localStorage/sessionStorage/cookie 保存密钥，不加载第三方脚本、字体或埋点。
- 写入和删除必须有平台登录身份、匹配的Origin，并拒绝跨站请求。所有响应no-store；限制请求体1KiB。密钥只能发送给固定DeepSeek终点，浏览器无法指定转发地址。
- 启用线上个人密钥存储后，每个访客只用自己的密钥；没有个人密钥时不会回退到站主环境变量，避免其他访客消耗站主额度。平台访问范围保持原有私有设置。
- 这是一套应用层凭据保管机制，不宣称端到端加密或运营方绝对无法访问：服务端运行时必须解密密钥以调用DeepSeek。不要读取或记录生产凭据对象。托管平台的基础设施日志和备份策略属于平台范围，不以应用“不记录正文”代替这些保证。

独立Node源码包不包含托管登录和R2，连接页会提示不可配置；该版本仍按上面的本地`.env`方式配置。线上接入不要求用户下载源码或运行终端。

## 实际会发送什么

请求只包含：已收录的食材名称、厨具名称、调料名称、人数、时间、不吃的食材名称、优先消耗的食材名称。自由输入先在浏览器归一化，服务器再次白名单校验。数量描述和未识别文字不上传。

后端只发送一段固定的做饭系统提示和上述单次JSON数据。不会从当前ChatGPT对话读取或附带聊天记录、个人记忆、历史请求、账号资料、浏览历史、Cookie、来源页面、浏览器IP头或平台访问凭证。接口不保存请求正文、不记录密钥或模型响应正文，也不建立多轮会话。

这不等于第三方“绝不留存”：**DeepSeek会收到用户确认的做饭数据及服务端调用所必需的网络信息**，其处理和留存由服务商政策决定。`store:false` 是保留的OpenAI适配参数，不把它发送给DeepSeek，也不将其当作DeepSeek零留存保证。

## 返回结果

模型返回必须符合字段、数量、厨具、时间与食材约束；已知清单外的配料、调料和厨具描述会被过滤。不把未经检查的模型文本当HTML执行，不把供应商原始错误或诊断返回前端。此校验不能替代人工核对，尤其不能证明复杂过敏安全或全部步骤正确。

AI新增菜品没有对应成品插图时，显示“AI文字食谱”；只有菜名和食材组合与内置菜谱完全相同才借用该菜插图，避免错误图片。

## 请求限制和访问范围

请求最多8KiB，上游响应限96KiB；每个服务实例同时最多1次生成，每分钟最多6次。限流只在当前实例内存中，**不是跨实例的全站计费上限**。当前托管网站延续原有私有访问范围。公开前应补全可靠的用户鉴权、持久化配额与账户预算限制，不能把目前的基础限流当作消费保障。
